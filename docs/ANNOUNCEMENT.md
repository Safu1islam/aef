> The expensive one: an agent asked for a latency-critical system reaches for whatever
> language it writes most fluently. You find out after it exists.
>
> AEF forces constraints on the page before any technology is named — and makes the
> agent state which choice it would have made by habit.

**3/**
> The invisible one: agents fabricate mock data to make a demo run, then never record
> it. Months later nobody can tell fake from real.
>
> Every stub is registered at creation with a replacement condition. Completion is
> blocked while anything it depends on is still fake.

**4/**
> The dishonest one: "all tests passing" when nothing ran.
>
> Six statuses. PASSED requires that the agent executed it and observed success.
> NOT_RUN is an acceptable, honest answer. There is no room to be vague.

**5/**
> Not 300 specialist agents. Seven roles, any model can occupy any of them, plus 45
> quality dimensions that load only when the change requires them.
>
> Rollback plans, threat models, retention, observability — mandatory by change class,
> from config. Not left to the agent's mood.

**6/**
