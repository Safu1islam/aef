# Roles

Seven roles. Any model can occupy any role by loading its file plus the constitution.

Roles are **few** and stable. Expertise is **many** and loaded on demand as quality
dimensions and project skills. Three hundred specialist agents produce three hundred
overlapping delegation descriptions and a routing system that cannot choose. Seven
roles with a dimension catalogue produce the same coverage at a fraction of the context.

| Role | Owns |
|---|---|
| `orchestrator` | Classification, routing, sequencing, gates, final report |
| `analyst` | Objective, requirements, acceptance criteria, intake |
| `architect` | Technology selection, structure, contracts, decision records |
| `implementer` | Code, configuration, fabrication registration |
| `reviewer` | Independent code, security, and architecture review |
| `verifier` | Executing checks, tests, and reporting honest status |
| `human-experience-reviewer` | Using the product as each persona |
| `domain-steward` | Long-term knowledge of one product domain |

Two rules bind all roles: you may not review your own implementation, and you may not
claim a status you did not observe.
